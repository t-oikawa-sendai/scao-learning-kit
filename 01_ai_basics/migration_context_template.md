# AI専用・新チャット文脈移行プロトコル

新チャット開始時に本プロトコルを最初に読み込む。確定事項・採用判断・却下案・未決事項・現在状態を混同せず、次工程を一意に判断できる状態を引き継ぐ。

## [PROJECT_METADATA]

プロジェクトと作業環境の識別情報を記載する。

- **PROJECT_NAME**: {{プロジェクト名}}
- **REPOSITORY_URI**: {{リポジトリURL／なし}}
- **LOCAL_WORKSPACE_PATH**: {{ローカル絶対パス}}
- **CURRENT_GIT_BRANCH**: {{ブランチ名}}
- **TARGET_ENVIRONMENT**: {{OS、言語バージョン、DB、IDE等の環境スタック}}

必要に応じて以下を追加できる（必須ではない）。

- **PRIMARY_SPEC_OR_SSOT**: {{正本仕様書・設計書・README等のパス}}
- **CURRENT_PHASE**: {{調査／設計／実装／文書整備／レビュー等}}

### 現在のチャットまたは作業の具体的な目的

## [BACKGROUND_AND_PREMISES]

背景・制約・経緯を記載する章である。確認済みの事実（CONFIRMED_FACTS）や採用判断（ADOPTED_DECISIONS）と混同しない。

- **業務背景**: {{なぜこのプロジェクト・作業が必要か}}
- **作業開始の経緯**: {{いつ・誰の指示・どのきっかけで開始したか}}
- **対象利用者**: {{エンドユーザー、運用者、読者等}}
- **現在のフェーズ**: {{開発・文書整備・調査・レビュー等の段階}}
- **技術的・運用上の制約**: {{使用技術、期限、変更禁止範囲、環境制約等}}
- **判断の前提**: {{意思決定の土台となる仮定・方針}}
- **正本の位置づけ**: {{どの文書・リポジトリ・ブランチを正とするか}}

- **F-002**: {{確認済みの事実}}

## [CURRENT_STATUS]

- **WORK_PRODUCT_STATUS**: {{実装、設計、文書、調査等の現在状態}}

- **BUILD_STATUS**: {{SUCCESS / FAILED / NOT_APPLICABLE / 未確認}}

## [SOURCE_FILES]

新チャット開始時に参照すべき正本ファイルを、優先順に記載する。

1. {{正本ファイル（リポジトリ相対パスまたは絶対パス）}}
2. {{補助資料（正本より後に記載）}}

**記載ルール**

- 正本を先に、補助資料を後に記載する
- ローカル絶対パスとリポジトリ相対パスを混在させる場合は、どちらかを明記する
- 存在未確認のファイルは「未確認」と明記する
- 秘密情報を含むファイルは記載しない

## [NEXT_ACTION]

次工程の指示を4区分で記載する。

### IMMEDIATE_TASK

新チャット開始直後に実行する最初の作業を1つだけ記載する。複数工程をまとめない。

- {{最初に実行すべき単一の作業}}

### EXPECTED_OUTPUT

次工程で求める成果物、報告内容、判断結果を記載する。

- {{期待する成果物・報告・判断}}

### DO_NOT_DO_YET

次工程ではまだ実施してはいけない一時的禁止事項を記載する。

- {{実装、commit、push、対象外変更等の禁止事項}}

### STOP_CONDITIONS

作業停止が必要な条件を記載する。

- 正本不一致
- Git状態不一致
- 仕様矛盾
- 対象外変更が必要
- 秘密情報検出
- 破壊的操作が必要
- commit・pushの判断が必要（明示的許可がない場合）
- 実装許可がない
- 必須情報不足

## [GUARD_RAILS]

プロジェクト全体で継続して守る恒久的な制約を記載する。

- 事実、推測、未確認事項を分離する
- 正本未確認情報を事実として扱わない
- 公式仕様や確定ソース（Fact）にない仕様を推測（Inference）で補完しない。不明点は未確認事項として残す
- 却下済み案を理由なく再提案しない
- 指示のない実装、リファクタリング、機能拡張を行わない
- 対象外ファイルを変更しない
- 既存の確定仕様や動作確認済みコードを破壊・退行させる変更を提案・実装しない
- 秘密情報・個人情報・認証資格情報を出力しない
- 破壊的操作（force push、hard reset、本番データ削除等）を無断で行わない
- 変更履歴の正本（CHANGELOG等）と整合させる

## [HANDOFF_VALIDATION]

引き継ぎ内容を自己検証し、作業開始可能かを判定する。

- **重要な確定事項の欠落**: {{なし／あり}}
- **採用方向の欠落**: {{なし／あり}}
- **却下案の欠落**: {{なし／あり}}
- **未決事項の欠落**: {{なし／あり}}
- **正本未反映の決定**: {{なし／あり。内容}}
- **SAFE_TO_CONTINUE**: {{YES / CONDITIONAL / NO}}

### SAFE_TO_CONTINUE 判定基準

**YES** — 以下をすべて満たす場合。

- 重要事項の欠落なし
- ブロッカーなし
- 正本確認済み
- 次工程が一意
- 次工程の実施許可あり

**CONDITIONAL** — 以下の場合。

- 未確認事項が残る
- 限定された調査・レビューのみ可能
- 実装、変更、commit、pushはまだ開始できない

**NO** — 以下のいずれかに該当する場合。

- 正本不一致
- 仕様矛盾
- 重要事項の欠落
- 秘密情報または個人情報の検出
- 破壊的操作の危険
- Git状態が不明
- 次工程が一意に定まらない
- ブロッカーが未解消
